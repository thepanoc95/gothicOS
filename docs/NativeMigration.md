# NullKernRT native migration

NullKernRT is now a multi-language stack. The native core is C, with Rust and C++ layers
on top, C++ drivers, and a MicroPython chainloader that preserves the original boot path.
All layers speak the unchanged stable ABI in
[`SDK/include/gothicos/kernel_abi.h`](../SDK/include/gothicos/kernel_abi.h) (v1.1.1).

## Layers

| Layer | Path | Responsibility |
| --- | --- | --- |
| Native core (C) | [`kernel/core/c/nk_core.c`](../kernel/core/c/nk_core.c) | Freestanding scheduler, IPC, ports, pools, IRQs, boot and ABI dispatch. No libc, allocation, threads or platform calls. |
| Native core contract | [`kernel/core/include/gothicos/nk_core.h`](../kernel/core/include/gothicos/nk_core.h) | Fixed-size kernel storage and host entry points shared by every port. |
| Core (Rust) | [`kernel/core/rust`](../kernel/core/rust) | `no_std` facade over the C core using caller-provided aligned storage. `build.rs` compiles the C source into a static library. |
| HAL (C++ / Rust) | [`kernel/hal/cpp`](../kernel/hal/cpp), [`kernel/hal/rust`](../kernel/hal/rust) | Platform abstraction: topology, clocks, logging and CPU binding. Both HALs reject CPU 0 in the hosted configuration. |
| KAL (C++ / Rust) | [`kernel/kal/cpp`](../kernel/kal/cpp), [`kernel/kal/rust`](../kernel/kal/rust) | Typed, safe interfaces over `nk_invoke`. |
| Drivers (C++) | [`kernel/drivers/cpp`](../kernel/drivers/cpp) | C++ drivers registered through ABI trampolines (`console`, `timer`). |
| Linux handoff | [`kernel/linux/handoff.c`](../kernel/linux/handoff.c) | Platform-neutral, opt-in state machine: bind CPUs, load init ELF, start init, start services. |
| Linux module | [`ports/linux/nullkern_lkm.c`](../ports/linux/nullkern_lkm.c) | `/dev/nullkern` transport plus confined handoff ioctls; compiles the C core and handoff machine directly into the module. |
| MicroPython chainloader | [`ports/micropython`](../ports/micropython) | `null.boot()` → init ELF → UmbraTS shell. |

The C core stores everything in a caller-supplied buffer. The same object file can be
linked into firmware, a userspace shared library, the Rust crate or the Linux module. The
Rust `KernelStorage` reserves 192 KiB and the C++ KAL allocates `nk_kernel_storage_size()`
bytes, so no layer assumes a process heap inside the kernel.

## Safety model

The Linux handoff is **bare-metal, confined and opt-in**. It never enumerates or
terminates host processes.

- The module parameter `handoff=1` or `HANDOFF_START` with `enabled=1` is required; the
  default is a passive `/dev/nullkern` character device.
- `HANDOFF_START` requires `CAP_SYS_ADMIN`.
- CPU 0 is always reserved for Linux. `first_managed_cpu` defaults to 1, and every CPU
  binding hook rejects 0 and out-of-range CPUs.
- Only NullKern-owned kthreads are created. They are bound to CPUs 1..N-1 and stopped by
  `HANDOFF_STOP` or module unload.
- The init ELF is opened, magic-checked, size-limited and retained. Kernel-side execution
  of arbitrary ELF images still requires a firmware/sandbox loader and is intentionally
  not enabled here. The Rust and MicroPython paths can run the embedded Umbra payload
  without a kernel ELF loader.
- This is a lab feature: do not enable it on production hosts.

## MicroPython boot chain

```text
MicroPython
  null.mpy -> null.boot('-v -debug=0x01 -root=@flash/data -mem=200K')
  -> osloader.py          boot facade and compatibility alias installation
  -> boot_config.py       parse options, resolve @flash paths
  -> init.d.elf           parse ELF, extract .umbra payload
  -> null_kernel.py       takeover: bind CPUs 1+, boot core, register init/services
  -> umbra_shell.py       run @flash/data/user/bin/sh.uts via UmbraTS
```

`BootOptions` derives both conventional paths from `-root`:

- `@flash/data/system/init.d.elf`
- `@flash/data/user/bin/sh.uts`

The embedded `.umbra` section generated by [`ports/micropython/build.py`](../ports/micropython/build.py)
is preferred over a separate `sh.umb` file, so the shell really is carried by the loaded
init image. The separate file remains as a fallback on devices without an ELF section
reader.

The canonical device entry point is `null.boot()`; `os.boot(...)` remains as a
compatibility alias. Some MicroPython ports (including the Pico W build tested here) make
the built-in `os` module immutable. `osloader.install()` then installs a small proxy in
`sys.modules`, so import `osloader` before `os` in scripts that use the compatibility
alias.

The default `sh.uts` is an interactive UmbraTS command loop, not a one-shot banner. On a
device, `null.boot()` bridges serial input into the `shell.in` kernel port; the UmbraTS task
owns the prompt and command dispatch. Available commands are `help`, `info`, `exit`/`quit`,
and free-form text, which is echoed back. Pressing Ctrl-C or Ctrl-D at the prompt exits the
shell and returns to the MicroPython REPL. The bridge reads directly from `sys.stdin`
because MicroPython's `input()` is not reentrant from code called at the REPL. Tests inject
`input_fn` instead of using stdin.

## Linux ioctls

The shared header now exposes seven ioctls. The original four are unchanged:

| Ioctl | Purpose |
| --- | --- |
| `GET_INFO` | ABI version, counters and open nodes. |
| `RAISE_IRQ` | Increment the IRQ counter and wake waiters. |
| `PORT_SEND` | Increment the message counter and wake waiters. |
| `SCHED_HINT` | Increment the scheduling-hint counter. |
| `HANDOFF_STATUS` | Copy the 512-byte handoff state to userspace. |
| `HANDOFF_START` | Opt-in start using the 16-byte handoff request. |
| `HANDOFF_STOP` | Stop owned kthreads and reset the handoff state machine. |

The Cython `LinuxPort` exposes matching `handoff_status()`, `handoff_start()` and
`handoff_stop()` methods. `handoff_start()` refuses `enabled=False` and `first_managed_cpu=0`.

## Build and test

```sh
# C, C++, Rust shared/static libraries
make -C kernel all

# Rust workspace tests (offline)
cargo test --workspace --offline --manifest-path kernel/Cargo.toml

# MicroPython flash tree (init ELF + sh.umb)
python ports/micropython/build.py

# Python, C, C++, Rust and chainloader checks
python -m unittest discover -s tests -q

# OSBuild recipe validation
gothicos validate --config kernel/build.json
gothicos validate --config ports/micropython/build.json
```

`kernel/build.json` is a command recipe because OSBuild source recipes currently accept
only `.py`, `.pyx` and `.c` inputs; C++ and Cargo are driven by `kernel/Makefile` instead.
`ports/micropython/build.json` is a normal source recipe that compiles the chainloader
modules to `.mpy` and runs `build.py` to prepare the flash tree.

Building the loadable Linux module still requires matching kernel headers:

```sh
make -C ports/linux
sudo insmod ports/linux/nullkern_lkm.ko handoff=1 first_managed_cpu=1
```

The native sources are included directly by `nullkern_lkm.c`, so no extra objects need to
be listed in the kbuild Makefile.

## Current boundaries

- The module does not execute the init ELF in kernel mode; it registers a one-shot init
  anchor and retains the verified image. Full ELF execution belongs in a dedicated
  firmware/sandbox loader, not in the LKM.
- The C core is deterministic and cooperative. It is not an SMP-preemptive kernel;
  managed threads serialise access to the native core with a kernel mutex.
- C++ and Rust HALs expose the same conceptual contract but do not share a single vtable
  across languages; the stable boundary remains `kernel_abi.h`.
